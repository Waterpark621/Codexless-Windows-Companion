# Artifact provenance

Codexless package provenance, Node executable provenance and tunnel-client provenance are distinct gates. Manifest verification binds the qualified Codexless source payload; it does not certify a Node or tunnel executable.

`ARTIFACT-POLICY.json` pins the Windows x64 ZIP for the already-qualified Node 24.12.0 version to the official `nodejs.org` distribution and SHA-256 from its official SHASUMS256.txt. This is a reviewed checksum pin obtained through HTTPS, not a claim that OpenPGP signature verification was performed. Other architectures require their own explicit qualification.

`Save-QualifiedArtifact` permits only the exact policy URL, HTTPS, HTTP 200, at most one bounded GitHub release-asset redirect to the official asset CDN for the pinned tunnel asset or a future exact Waterpark621/Codexless release URL, explicit deadline and byte limit, and a fresh staging directory. Partial failures remain staged and are never promoted or executed. `Expand-QualifiedArtifact` hashes and extracts through one locked archive stream, preflights every entry for traversal, aliases, case-insensitive collisions, links and size/count limits, and refuses an existing destination. It does not register tasks, start executables or promote an installation.

Codexless distribution binding is implemented as one fail-closed slot in `ARTIFACT-POLICY.json`. It freezes candidate HEAD `1bc8b5f6f45b88cc4bc311604178407992bcc9d2`, version `0.1.2-preview.1`, build ID `7e416d0f32e67cffa6af1ba9ea4339dc738fdc86115263336229cc9fd46c8308`, source revision `1da3cb5b8563370f3656c831d17a1c73354df282`, release-manifest SHA-256 `14583de39b1218ff44477b62519f7cc6351ec7c33259cf24c334ef0ed5cccb9d`, host contract `codexless-public-preview-v1`, ZIP format, expanded bounds, and the direct-root installable payload shape. The actual clean Codexless candidate is not published, so this slot deliberately remains `state: unpublished` with `url`, `archiveFileName`, and archive `sha256` set to null. Partial publication data is invalid, and `Get-ArtifactPolicy codexless` refuses before download or staging mutation.

After the exact candidate is published, the only Codexless publication fields to populate are `state=published`, the immutable HTTPS archive URL, the exact archive filename, and the exact archive SHA-256. The filename must be the URL leaf and a safe `.zip` name. A direct HTTP 200 response is accepted; if the exact pinned URL is under `github.com/Waterpark621/Codexless/releases/download/`, exactly one HTTPS redirect to GitHub's official `release-assets.githubusercontent.com/github-production-release-asset/` surface is accepted, with the signed target retained only in memory. No local tarball/archive path, machine URL, download-time trust-on-first-use, or guessed public identity is accepted.

`Stage-QualifiedCodexlessDistribution` is the integration entry point for Worker A/coordinator after publication: it fails on policy first, downloads and hashes the exact archive, safely extracts it, verifies the exact release-manifest bytes, checks version/build/source/host identity, hashes every manifest-controlled file, requires `scripts/launch.mjs` to be controlled, rejects unexpected files through payload closure, and only then returns a qualified staged root with `promoted=false`. `Stage-QualifiedCodexlessArchive` provides the same archive/extraction/root qualification for an already-supplied exact archive and is used by local fixtures; it remains policy/hash gated.

Automatic installer mutation remains disabled. Exact fresh-generation tunnel connect is now qualified separately. A pinned archive is only one prerequisite for transactional promotion; it does not establish a generation, process lifetime, update/rollback or second-machine acceptance.

The approved tunnel distribution is the official OpenAI v0.0.14 Windows amd64 full client. Both archive and extracted executable hashes are pinned. The pinned GitHub asset may redirect once to the HTTPS official release asset CDN; Node redirects and further redirects remain forbidden. Signed CDN URLs stay in memory; no origin credentials or cookies are forwarded. Unsigned executable policy compatibility remains a clean-machine acceptance gate. Security controls must never be bypassed. Qualification alone does not enable automatic connect.
